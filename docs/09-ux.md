# 09 — User Experience Specification

> **Purpose:** Page-by-page UX for the portfolio: sections, content, animations, interactions, and responsive behavior. Builds on the content in `01`–`07` and the visual system in `08-design.md`. No code.
>
> **UX principle:** *Every page answers one question for one reader, in the first screen, then rewards those who keep reading.*

---

## Part A — Global Experience

### A1. Site Map & Navigation

```
Home  /
About  /about
Experience  /experience
Domain Expertise  /domain
Case Studies  /work  →  /work/{{slug}}
Open Source  /open-source
Skills  /skills
Resume  /resume
Contact  /contact
```

**Primary nav (desktop):** Work · Experience · Domain · Open Source · About · **[Contact]** (filled button)
**Secondary (in "More" or footer):** Skills · Resume
**Why:** Seven top-level links overload the header. Skills and Resume are reached constantly through in-page links and the footer. About links to Skills.

### A2. Global Header
| State | Behavior |
|---|---|
| Top of page | Transparent background, full-height (72px), monogram + nav + Contact button |
| After scrolling 80px | Shrinks to 56px, gains solid surface + hairline bottom border (200ms ease-out) |
| Scrolling down fast | Hides (slides up 100%) to give reading room |
| Scrolling up | Reappears immediately |
| Inside case-study detail | Shows a thin reading-progress bar along its bottom edge |

- **Active page** is marked with an accent underline that slides between items when you change pages (shared-element transition).
- **Theme toggle** (sun/moon icon) sits left of the Contact button and remembers the choice.
- **Availability dot** next to the monogram: green pulse = "Open to roles". Hover/tap shows a tooltip: "Open to Lead / Senior roles in Seattle — `{{DATE}}`".

### A3. Global Footer
- Left: name, one-line positioning, "Seattle, WA".
- Middle: all nine page links (two columns).
- Right: email (copy button), LinkedIn, GitHub, Résumé download.
- Bottom row: "Last updated `{{DATE}}`" · "Built with `{{STACK}}` — source on GitHub" · privacy note.
- Optional subtle topographic-line motif (Cascades) fading in at the very bottom.

### A4. Command Palette (power-user delight)
- Opens with `⌘K` / `Ctrl K`, or the search icon in the header.
- Search across pages, case studies, projects, skills, and actions ("Copy email", "Download résumé", "Toggle theme", "Book a call").
- Keyboard: ↑↓ to move, Enter to open, Esc to close.
- A shortcut hint appears in the footer only (never interrupts).
- **Why:** Engineers reviewing the site recognize and appreciate it. It signals craft without getting in the way.

### A5. Page Transitions
- Leaving page: content fades to 0 and shifts up 8px (150ms).
- Entering page: content fades in and rises 12px → 0 (250ms, ease-out).
- Case-study card → detail: the card's title and hero metric **morph** into the detail page header (shared-element transition, 350ms).
- With `prefers-reduced-motion`: instant swap, no movement.

### A6. Motion System
| Token | Duration | Easing | Used for |
|---|---|---|---|
| `instant` | 100ms | linear | Hover color, focus ring |
| `quick` | 150–200ms | ease-out | Buttons, chips, tooltips |
| `standard` | 250–300ms | cubic ease-out | Cards, accordions, page enter |
| `expressive` | 400–600ms | spring (low bounce) | Hero intro, shared-element morphs, number count-ups |
| `stagger` | 40–60ms between items | — | Lists and grids revealing |

**Rules**
1. Motion explains change (where something came from, what changed). It is never decoration.
2. Content is always readable before its animation finishes. No text is hidden waiting on a script.
3. Scroll reveals run **once** per element, trigger at 15% visibility, and move ≤ 16px.
4. No parallax on text, no scroll-jacking, no autoplaying video with sound.
5. `prefers-reduced-motion`: replace all transforms with simple opacity fades ≤ 150ms; count-ups show final values.

### A7. Interaction Standards
| Element | Hover (pointer) | Focus (keyboard) | Press / tap | Disabled / loading |
|---|---|---|---|---|
| Primary button | Background darkens 8%, arrow icon nudges 2px right | 2px accent outline, 2px offset | Scales to 0.98 | Spinner replaces icon, label stays |
| Text link | Underline animates in left→right | Outline + underline | — | — |
| Card | Lifts 2px, shadow deepens, border tints accent | Full-card outline | Scales to 0.99 | Skeleton shimmer |
| Chip / tag | Background tints | Outline | Toggles filled state | — |
| Copy button | Tooltip "Copy" | Same | Icon → ✓ and toast "Copied" (2s) | — |

- **Whole card is clickable**, with a single real link inside (accessible pattern). Secondary links within the card stay independently focusable.
- **Tooltips** appear after 300ms on hover, immediately on focus, and as tap-to-toggle on touch.
- **Toasts** appear bottom-center on mobile, bottom-right on desktop, and are announced to screen readers.

### A8. Responsive Framework
| Breakpoint | Name | Grid | Gutter | Nav |
|---|---|---|---|---|
| < 640px | Mobile | 4 col | 16px | Hamburger → full-screen sheet |
| 640–959px | Tablet | 8 col | 24px | Hamburger → side drawer; Contact button stays visible |
| 960–1279px | Laptop | 12 col | 32px | Full inline nav |
| ≥ 1280px | Desktop | 12 col, max 1120px content | 32px | Full nav; sticky side TOCs appear |

**Mobile nav sheet:** slides up from bottom (300ms). Shows large tap targets (56px rows), the Contact + Résumé buttons pinned at the bottom, and theme toggle. Closes on swipe-down, Esc, backdrop tap, or link tap. Focus is trapped inside while open.

**Universal mobile rules**
- Tables become stacked "label: value" cards.
- Hover-only content always has a tap equivalent.
- Touch targets ≥ 44×44px; spacing between targets ≥ 8px.
- Horizontal scroll is used only for clearly signposted carousels (with edge fade + "swipe" hint the first time).
- Sticky bottom action bar on key pages (Case Study detail, Resume, Contact).

### A9. States
- **Loading:** skeletons matching the final layout (no spinners for page content).
- **Live data failure** (e.g., GitHub stars): quietly show the last cached value with "as of `{{DATE}}`"; never show an error to the visitor.
- **404:** "This page went off-call." Links to Home, Work, and Contact, plus the command palette hint.
- **Offline:** banner "You're offline — showing saved pages."

## 1. Home `/`

**Goal:** In 30 seconds, a recruiter knows *who, what level, what specialty, where, and one proof point*, and knows where to click next.
**Primary reader:** Recruiter (scan), Hiring manager (entry point).

### Sections
| # | Section | Content | Source |
|---|---|---|---|
| 1 | **Hero** | Eyebrow (role · specialty · Seattle), outcome-led headline, 1–2 line subheadline, two CTAs (View case studies / Download résumé), availability badge, optional headshot | `01 §4` |
| 2 | **Proof bar** | 3–4 headline metrics in a single row (e.g., "Led 8 engineers", "$4M/yr saved", "99.99% uptime", "2K★ OSS") | `01 §7` |
| 3 | **Selected Case Studies** | 3 cards: title, outcome subtitle, hero metric, role badge, pillar tags. "All case studies →" link | `04` |
| 4 | **How I Lead** | 3–5 principles, each with a one-line real example and link to evidence | `01 §6` |
| 5 | **Domain Snapshot** | Domain one-liner, 3 "hard problems solved" tiles, KPIs moved. "Explore domain expertise →" | `03 §1, §3–4` |
| 6 | **Architecture Highlight** | One featured before/after diagram with a 2-sentence caption ("The decision that mattered") | `04` flagship |
| 7 | **Open Source** | 2–3 project cards with role badge and live adoption metric | `05 §3` |
| 8 | **Career Snapshot** | Horizontal timeline of companies → titles, with scope badges | `02` summary strip |
| 9 | **What People Say** | 2–3 testimonials (manager, peer, report) | `07 §6` |
| 10 | **Contact CTA band** | "Building something in Seattle? Let's talk." + Email / Book a call / LinkedIn | `07 §3` |

### Animations
- **Hero intro (first visit only, ≤ 900ms total):** eyebrow fades in → headline appears word-group by word-group (staggered 60ms, rising 12px) → subheadline and CTAs fade in → availability dot begins a slow pulse. Repeat visits in the same session: everything is shown instantly.
- **Proof bar:** numbers count up from 0 over 600ms when 50% visible; units and labels are static so the meaning is clear at once.
- **Case study cards:** stagger in (60ms) on scroll.
- **How I Lead:** each principle's number (01, 02…) draws in with a short accent line.
- **Architecture Highlight:** diagram boxes appear in data-flow order (left→right), with the changed component highlighted in the accent color last.
- **Career Snapshot:** timeline line draws left→right as it enters the viewport; company nodes pop in along it.
- **Testimonials:** gentle cross-fade, *never* auto-rotating (user controls it).

### Interactions
- Proof-bar metric: hover/tap reveals a tooltip with context ("from 4h → 6min settlement, 2024, payments team") and a link to the case study.
- Case study card: hover lifts it and reveals a "Read case study · 6 min" line; click morphs into the detail page.
- Principle: click/tap expands an inline example (accordion) instead of leaving the page.
- Domain tiles: hover flips subtly to show "How I solved it" one-liner (on touch: tap to toggle; on keyboard: Enter).
- Architecture Highlight: a **Before / After** segmented toggle; also draggable comparison slider on pointer devices.
- Career Snapshot: hover/focus on a node shows title, years, team size; click goes to that role on `/experience#{{company}}`.
- Testimonials: arrow buttons and dot indicators; swipe on touch; keyboard arrows when focused.
- Résumé CTA: downloads PDF and shows a toast "Résumé downloaded — `{{FILE_SIZE}}`".

### Responsive
| | Mobile | Tablet | Desktop |
|---|---|---|---|
| Hero | Text only, headshot hidden or small circle above eyebrow; CTAs stacked full-width | Headshot right, 40% width | Text 7 cols, headshot 5 cols |
| Proof bar | 2×2 grid | 4 in a row, smaller type | 4 in a row |
| Case studies | Single column; or horizontal carousel with peek of next card | 2 columns (third below, full-width) | 3 columns |
| Principles | Accordion list | 2 columns | 3–5 in a row or 2-row grid |
| Architecture | Before/After toggle only (no slider) | Toggle | Slider + toggle |
| Career Snapshot | Becomes a **vertical** timeline | Horizontal, scrollable | Horizontal, full |
| Contact band | Sticky bottom bar appears after hero scrolls out: "Contact · Résumé" | Inline band | Inline band |

## 2. About `/about`

**Goal:** Show the person behind the work and how they lead. This is where culture fit is decided.
**Primary reader:** Hiring manager, team members on the interview loop.

### Sections
| # | Section | Content |
|---|---|---|
| 1 | **Intro** | Headshot, medium bio (≈150 words), location, "Currently" line (role, reading, learning) |
| 2 | **My Story** | Long narrative in 4–5 short chapters: Origin → Inflection point → Known for → How I lead → What's next |
| 3 | **Leadership Philosophy** | Principles in expanded form, each with a story and outcome |
| 4 | **How I Work** | "Working with me" guide: communication style, how I run design reviews, how I make decisions, what I need from a manager, what I give my team |
| 5 | **By the Numbers** | Signature numbers strip (engineers led, promoted, systems shipped…) |
| 6 | **Capabilities Preview** | 4 top capability cards → "See all skills" |
| 7 | **Beyond Work** | Hobbies, community, PNW life (photo strip optional) |
| 8 | **CTA** | "Want the short version?" → Résumé · Contact |

### Animations
- Headshot gently fades and scales from 0.96 → 1.
- **My Story:** a vertical progress line in the left margin fills as you read; each chapter's heading "lights up" (accent) when it is the active one.
- Principles reveal one at a time with a staggered rise.
- Numbers count up once.
- Beyond Work photos: slight rotation settle (−2° → 0°) as they enter, Polaroid-style. Kept very subtle.

### Interactions
- Story chapters double as a mini-TOC (sticky on desktop); clicking jumps with smooth scroll and updates the URL hash.
- "Working with me" items are expandable cards; an "Expand all" control exists.
- Each principle has a "See it in practice →" link to the specific case-study section (deep link to the anchor).
- Copy-link icon appears next to each heading on hover (shareable anchors).

### Responsive
- **Mobile:** headshot on top, centered; story TOC becomes a horizontal chip row that sticks under the header; "How I Work" cards stack; photo strip becomes a swipeable row.
- **Tablet:** two-column intro (photo + bio); TOC collapses into a "Jump to" dropdown.
- **Desktop:** 3-col layout: sticky TOC (left), reading column 680px (center), "Currently" / quick facts sidebar (right).

## 3. Experience `/experience`

**Goal:** Prove growing scope over time, from contributor to multiplier.
**Primary reader:** Recruiter (verifying titles/dates), Hiring manager (judging scope).

### Sections
| # | Section | Content |
|---|---|---|
| 1 | **Header** | Title, one-line career summary, years total / years leading, Résumé button |
| 2 | **Scope Growth Chart** | Small visualization: team size and scope over time (step chart), showing progression |
| 3 | **Filter Bar** | Chips: All · Leadership · Architecture · Business Impact · Reliability · Cross-functional · Open Source |
| 4 | **Timeline** | One card per role (newest first): company, title, dates, location, company context, scope badges (team size, scale, systems), mission, achievements, promotions, linked case studies, collapsed tech list |
| 5 | **Earlier Roles** | Condensed table |
| 6 | **Education & Certifications** | Cards with issuer logos and verify links |
| 7 | **Awards, Talks & Publications** | List with type icons |
| 8 | **CTA** | "Read how this played out →" (case studies) · Résumé |

### Animations
- Scope Growth Chart: line draws left→right (600ms), data points pop in; the current role pulses once.
- Timeline spine draws downward as the user scrolls; each role card slides in from the spine side (12px) and its dot fills with accent when the card is centered in view.
- Filtering: non-matching bullets **fade to 30% and collapse**, matching bullets get a brief accent highlight. Cards with zero matches collapse to a single line ("No Architecture items in this role"). 250ms, with layout animation so nothing jumps.
- Expanding a role: height animates; content fades in 100ms after.

### Interactions
- **Filter chips** are multi-select; the URL updates (`?focus=leadership`) so a recruiter can share a filtered view. A live count shows "12 items".
- Role card: collapsed by default except the current role. Click header to expand/collapse; "Expand all" control.
- Scope badges have tooltips explaining the number.
- Linked case-study chips open the case study; hovering previews its title and hero metric.
- Promotion markers inside a card (e.g., "Senior → Tech Lead 2024") have small up-arrow icons with dates.
- Hovering a point on the Scope Growth Chart highlights the matching role card, and vice versa.
- "Copy as text" on each role (for recruiters pasting into an ATS).

### Responsive
- **Mobile:** timeline spine moves to the far left edge (8px); cards go full-width; filter chips become a horizontally scrollable row that sticks under the header; Scope chart simplified to sparkline with start/end labels; tech list hidden behind "Show technologies".
- **Tablet:** spine at left, cards at 90% width; chart full-width above.
- **Desktop:** central or left spine, cards 8 cols; a sticky mini-map on the right lists companies and highlights the one in view (click to jump).

## 4. Domain Expertise `/domain`

**Goal:** Show business fluency: "This person understands our industry and its numbers."
**Primary reader:** Hiring manager, Director/VP, product partners on the loop.

### Sections
| # | Section | Content |
|---|---|---|
| 1 | **Header** | Primary domain, years in domain, domain one-liner |
| 2 | **How the Domain Works** | Interactive flow diagram: actors and core flow, with "where value is made" and "where systems break" annotations |
| 3 | **Hard Problems I've Solved** | Problem cards: Problem → Why it's hard → My approach → Outcome → Case study link |
| 4 | **Business Metrics I've Moved** | KPI tiles with before/after deltas and context |
| 5 | **Compliance & Risk** | Badges for standards worked under (PCI, SOC 2, HIPAA…) with role and outcome |
| 6 | **Technical Specialties** | Engineering-domain depth matrix (distributed systems, data, platform, reliability…) |
| 7 | **Secondary Domains** | Smaller cards |
| 8 | **Seattle Fit** | "Where this expertise applies": domain strengths mapped to the kinds of Seattle teams that need them |
| 9 | **Writing on this domain** | Articles and talks |
| 10 | **Glossary** | Domain terms explained simply (also powers tooltips site-wide) |

### Animations
- **Flow diagram** plays once on entry: a small "token" (e.g., a transaction dot) travels the flow path step by step (~3s total), each node highlighting as it passes. A Replay button is available. Reduced motion: static diagram with numbered steps.
- Failure-point annotations appear after the token passes, with a short shake-free red-dot pulse (one cycle).
- KPI tiles: before value shown, then animates to after value with a delta chip sliding in (▲ +2.1 pts).
- Problem cards stagger in.

### Interactions
- **Flow diagram:** click/tap any node to open a side panel (desktop) or bottom sheet (mobile) explaining that step, the systems involved, and which of your work touched it. Arrow keys move between nodes. "Step through" buttons (Prev/Next) for a guided mode.
- Domain jargon throughout the site is dotted-underlined; hover/tap shows the glossary definition.
- Problem cards expand inline to show the approach; "Full case study →" link.
- Compliance badges: tooltip with your role and outcome.
- Specialty matrix: click a row to filter case studies and projects that prove it (opens a filtered list in a drawer).

### Responsive
- **Mobile:** the flow diagram turns into a **vertical stepper** (one step per row, tap to expand), with an optional "View full diagram" that opens a pinch-zoomable full-screen view. KPI tiles in one column; problem cards as accordion.
- **Tablet:** diagram horizontal and scrollable with edge-fade; side panel becomes a bottom sheet.
- **Desktop:** diagram full-width; node detail opens in a right-side panel without leaving the page.

## 5. Case Studies

### 5a. Index `/work`

**Goal:** Help each reader pick the story most relevant to *their* role.

**Sections**
1. **Header:** "Selected work", one-line framing, count.
2. **Filter / sort bar:** Pillars (Leadership · Business Impact · Domain · Architecture · Open Source); sort by Impact or Recent.
3. **Featured case study:** a large card spanning full width (flagship).
4. **Grid:** remaining cards (title, outcome subtitle, hero metric, role badge, team size, timeline, tags, reading time).
5. **"Can't share everything" note:** brief explanation of confidentiality, offer to walk through details in conversation.

**Animations:** Featured card fades in with a slight scale (0.98 → 1). Grid staggers. Filtering re-flows the grid with layout animation (cards slide to new positions, removed cards fade out).

**Interactions:** Card hover lifts and shows "Read · 6 min". Filters are single-tap toggles with URL state. Hover on hero metric shows the before → after values.

**Responsive:** Mobile 1 column (featured card same size as others but with a "Featured" label); tablet 2 columns; desktop featured full-width + 2–3 column grid.

### 5b. Detail `/work/{{slug}}`

**Goal:** Prove judgment. A hiring manager should be able to run an interview off this page.
**Primary reader:** Hiring manager, Staff engineer interviewer.

### Sections
| # | Section | Content |
|---|---|---|
| 1 | **Header** | Title, outcome subtitle, reading time, pillar tags |
| 2 | **Snapshot card** | Company (or anonymized), my role, timeline, team, stakeholders, domain, key outcome |
| 3 | **TL;DR** | Problem / What I did / Result (3 bullets) |
| 4 | **Context & Business Problem** | Situation, urgency, cost of inaction |
| 5 | **Constraints** | Time, people, technical, organizational, compliance (icon list) |
| 6 | **My Role & Leadership** | Ownership vs. delegation, alignment, team setup, people growth |
| 7 | **Options Considered** | Trade-off table; chosen option highlighted |
| 8 | **Architecture** | Before/After diagrams, key decisions with rationale, non-functional targets met |
| 9 | **Execution** | Rollout strategy, risk mitigation, milestone timeline |
| 10 | **What Went Wrong** | Challenges and recovery (callout style) |
| 11 | **Results** | Metrics table: business, technical, team, people (before → after → change) |
| 12 | **Reflection** | What I'd do differently, lessons on leading |
| 13 | **Testimonial** | Optional quote |
| 14 | **Tech Used** | Collapsed |
| 15 | **Next / Previous + CTA** | Next case study card, "Discuss this in an interview → Contact" |

### Animations
- Header morphs in from the index card (shared-element).
- **Reading progress bar** in the header fills as you scroll.
- Snapshot card fades in with the header; the key outcome metric counts up.
- **Trade-off table:** rejected options dim slightly after reveal; the chosen row gets an accent left border that draws top→bottom, and a ✓ badge pops in.
- **Architecture diagrams:** Before diagram is shown first; switching to After animates the changed components (removed parts fade out, new parts draw in, moved parts glide). Unchanged parts stay still so the change is obvious.
- **Milestone timeline** draws as it enters.
- **Results:** each "after" value counts from the "before" value; the change chip slides in.
- "What Went Wrong" callout has a subtle amber left border that grows on entry.

### Interactions
- **Sticky table of contents** (desktop left rail): active section highlighted as you scroll; click to smooth-scroll; shows reading progress per section.
- **"Skim mode" toggle** at the top: collapses the page to TL;DR + Snapshot + Options + Results (for busy readers). State is remembered across case studies.
- **Diagrams:** Before/After toggle; click to open a full-screen lightbox with pan and zoom; hover a component to see a tooltip on its role and what changed; a "Describe this diagram" button reveals the text alternative.
- **Decision callouts:** "Why?" buttons expand the rationale inline.
- Metrics: hover/tap for context and measurement method.
- Copy-link icons on every heading.
- **Footnotes / glossary terms** open as popovers, never navigating away.
- End of page: "Next case study" card with preview; keyboard `←` / `→` moves between case studies when focus is not in a field.

### Responsive
- **Mobile:** TOC becomes a sticky "On this page ▾" pill under the header that opens a bottom sheet; Snapshot card becomes a 2-column key/value grid; trade-off table becomes one card per option, chosen option first and marked; diagrams are full-width with tap-to-open full-screen zoom (pinch); sticky bottom bar shows "Next case study · Contact".
- **Tablet:** TOC collapses to the pill; diagrams full width; tables scroll horizontally with sticky first column.
- **Desktop:** 3 zones: TOC rail (left), 680–720px reading column (center), margin notes / glossary popovers (right) on ≥ 1280px. Diagrams may break out wider than the reading column (up to 960px).

## 8. Resume `/resume`

**Goal:** Give recruiters exactly what they need to submit you internally, fast.
**Primary reader:** Recruiter, hiring coordinator.

### Sections
| # | Section | Content |
|---|---|---|
| 1 | **Action bar** | Download PDF · Print · Copy summary · Share link; "Last updated `{{DATE}}`" |
| 2 | **Web résumé** | HTML version matching the PDF: header (name, title, Seattle, links), summary, experience, selected impact, skills, education, certifications |
| 3 | **Recruiter Kit** | One-paragraph summary (copy), top 3 highlights (copy), links bundle (copy), work authorization & availability (as decided in `07`) |
| 4 | **Résumé variants** (optional) | Tabs: Technical Lead · Senior SWE (emphasis changes, same facts) |
| 5 | **References** | "Available on request" with relationship types (manager, peer, report) |
| 6 | **CTA** | Contact · Book a call |

### Animations
- Minimal by design: page-enter fade only. This is a utility page.
- Download button: icon transforms to a progress ring, then ✓.
- Variant tab change: content cross-fades (150ms); changed lines briefly highlight so readers notice what shifted.

### Interactions
- **Download PDF** uses a clear file name (`{{Firstname-Lastname}}-Technical-Lead-Resume.pdf`) and shows the file size before click.
- **Print** uses a print layout identical to the PDF (no nav, no footer, links shown as URLs).
- **Copy** buttons copy plain text formatted for email/ATS; toast confirms.
- **Share link** copies `/resume` URL (with variant parameter if selected).
- Each experience line in the web résumé links to the matching full entry on `/experience` or case study ("More detail →").

### Responsive
- **Mobile:** action bar sticks to the bottom as 2 large buttons (Download · Copy summary) with an overflow menu for Print/Share; web résumé single column; Recruiter Kit appears **first** on mobile (recruiters on phones usually want the copy-paste kit).
- **Tablet:** single column, action bar at top.
- **Desktop:** web résumé in a paper-like column (max 800px) with the Recruiter Kit as a sticky right sidebar.

## 9. Contact `/contact`

**Goal:** Turn interest into a conversation with the least effort possible.
**Primary reader:** Recruiter, hiring manager, OSS collaborator.

### Sections
| # | Section | Content |
|---|---|---|
| 1 | **Header** | Warm headline, availability status, reply-time expectation ("I usually reply within 24 hours") |
| 2 | **Quick Actions** | Three large tiles: Email (copy), Book a 20-min intro, LinkedIn |
| 3 | **Contact Form** | Name, email, company, reason (select), role link, message |
| 4 | **What I'm Looking For** | Roles, focus areas, work mode, Seattle area, availability date |
| 5 | **Elsewhere** | GitHub, blog, social links |
| 6 | **Testimonials** | 1–2 short quotes for final reassurance |

### Animations
- Availability dot pulses gently (stops after 3 cycles).
- Quick-action tiles stagger in.
- Form: labels float above fields on focus; field borders animate to accent.
- Submit: button → spinner → morphs into a ✓ success card that replaces the form (height animates smoothly), showing "Thanks, `{{name}}` — I'll reply within 1–2 business days."
- Error: field shows message below with a short fade (no shaking).

### Interactions
- **Email tile:** primary action copies the address (toast "Email copied"); secondary icon opens the mail app.
- **Book tile:** opens the booking tool in an embedded modal on desktop, a new tab on mobile.
- **Form behavior:**
  - Validation on blur, not on every keystroke; errors are specific ("Please enter a valid email").
  - "Reason" selection adapts the message placeholder (e.g., Hiring → "Tell me about the team, the role, and the problem you're solving.").
  - Role link field validates URL format and shows a preview of the domain.
  - Drafts are kept locally if the visitor navigates away and returns.
  - Submit is disabled only while sending; double-submit is prevented.
  - Spam protection is invisible (honeypot + rate limit).
  - On network failure: keep the message, show "Couldn't send — copy your message and email me directly," with a copy button.
- Keyboard: Enter moves through fields; `⌘/Ctrl + Enter` submits from the message box.

### Responsive
- **Mobile:** quick actions first as full-width stacked buttons (Email · Book · LinkedIn); form below; correct keyboard types (email keyboard for email, URL keyboard for role link); submit button full-width and sticky above the keyboard when the message field is focused.
- **Tablet:** quick actions in a row of three; form full width.
- **Desktop:** two columns: left = header, quick actions, "What I'm looking for"; right = form card (sticky as the left column scrolls).

## Part D — Accessibility Checklist for Interactions
- All interactive diagrams have keyboard navigation and a text alternative.
- Count-ups, flows, and morphs have reduced-motion fallbacks showing the final state.
- Accordions use proper disclosure semantics; filters announce result counts.
- Modals, drawers, and sheets trap focus, close on Esc, and return focus to the trigger.
- Toasts and form results are announced via live regions.
- No information is available on hover only.
- Color contrast ≥ 4.5:1 for text, ≥ 3:1 for UI and diagram strokes.
